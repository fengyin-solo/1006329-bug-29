# 城市地下综合管廊运行维护管理平台

面向管廊主体台账、入廊管线登记、廊内环境监测、通风排水消防、结构沉降与渗漏处置、巡检检修与隐患整改、入廊作业审批和运维值班的一体化城市地下综合管廊运行维护管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 顺序流转规则

所有模块的动作都沿 `modules.ts` 中 `statuses` / `transitions` 定义的链路推进，跳档一律打回，
提示语会写清当前卡在第几段、需要先推进到哪一段。

- **设施检修**：`待开工 → 检修中 ⇄ 已延期 → 已完工`。申请延期只受理检修中；延期件复工后仍可完工。
  确认完工用弹窗一次提交**完工日期、更换部件（未换填「无」）、完工结论**，状态与三项内容同一事务落库。
  同一记录重复完工只落一次（幂等）。列表与详情抽屉读同一份 localStorage，不存在两处口径。
- **完工 → 设备台账联动**：完工结论追加写入对应设备（检修对象中的 `DEVI-xxxx`）的「保养计划」，
  并为该设备幂等追加一条「待保养」记录（带 `来源检修单`），保养闭环后方可复役。
- **巡检 → 值班遗留**：巡检「上报问题」自动在值班交接表落一条有遗留记录（`来源巡检单`），
  两个页面的遗留条数都从值班表同一查询得出。
- **设备 / 值班 / 作业审批**：登记运行→完成保养→报废、发起交接→（登记遗留）→确认交接、
  提交审批→批准/驳回→完工，同样禁止跳档。

### 存量检修记录的计划工期回填（裁决规则）

早年只有完工日期、没有计划工期的单据：**以完工日期为计划工期末日**，按检修类别取标准工期向前倒推
（自然日含首尾）——大修 15 天、小修 3 天、常规检修/类别缺失 7 天。依据：完工日是唯一可信锚点，
取工期末日不会产生「计划末日晚于实际完工」的矛盾；工期天数采用常见检修定额档位。
仍在检修中且计划末日早于当天的，回写为「已延期」；有完工日期的存量单据统一回写「已完工」，
消除列表与详情状态对不上的问题。该迁移随 localStorage schema v1 → v2 自动执行一次（幂等）。

## 往期单据归档规则

- **按抄表周期搬入**：每条明细必须带 `关联抄表周期`（YYYY-MM），按周期与能耗台账核对。
- **纸面件建账**：早期只有纸面的按扫描件编号 `PAPER-<周期>-<顺序号>` 建账，来源记「纸面扫描件」。
- **重复导入只留最早版**：以材料编号/扫描件编号为身份键，重复导入直接丢弃，不会多出一行。
- **新旧版本冲突仲裁**：以**导入时间更晚的新版为准**，旧版置「已留痕」终态（不删档、保留原数值追溯），
  新版走 待办→办理中→已核对→已归档。依据：归档目的是账实一致，后形成的单据更接近设备与表计现状、
  通常包含勘误与复核结论；形成日期不决定效力，避免旧纸面誊抄件仅凭日期早就覆盖新电子件。
- **账实一致**：导入明细按「计量点位 + 抄表周期」与能耗台账逐项核对，用电量/用水量完全一致才建账；
  任一条对不上，**整批打回**（不建账、不留痕）。
- 流转次序固定：待办 → 办理中 → 已核对 → 已归档（冲突旧版 → 已留痕），跳档一律不认。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 顺序守卫在 `src/data/workflow.ts`，检修完工/存量回填在 `src/data/maintenance.ts`，
  跨模块联动（设备台账、值班遗留）在 `src/data/linkage.ts`，归档导入与仲裁在 `src/data/archive.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `urban-utility-tunnel:entries` 与 `urban-utility-tunnel:schema` 两项，
  或调用 `resetModule(模块)`。
